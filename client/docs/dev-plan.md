# 📋 DayLog - 할일 + 회고 다이어리 개발 계획서

## 1. 프로젝트 개요

### 서비스명
**DayLog** (데이로그)

### 한 줄 소개
하루의 할일을 관리하고, 하루 끝에 짧은 회고를 남기는 개인 다이어리 웹 서비스

### 기획 배경
- 단순 투두리스트는 "뭘 했는지"만 남고, "뭘 느꼈는지"는 사라짐
- 할일 완료 내역과 회고를 연결하면 성장 기록이 자연스럽게 쌓임
- 개발자 본인이 매일 직접 사용할 수 있는 실용적인 서비스

### 타겟 사용자
- 매일 학습/작업 내용을 기록하고 싶은 사람
- 단순 할일 관리 + 하루 돌아보기를 한 곳에서 하고 싶은 사람

## 2. 핵심 기능

### 기능 1: 할일 관리 (Todo)
| 항목 | 설명 |
|------|------|
| 할일 추가 | 제목, 카테고리 입력 후 등록 |
| 할일 완료/미완료 | 체크박스 토글로 상태 변경 |
| 할일 삭제 | 개별 삭제 |
| 날짜별 조회 | 특정 날짜의 할일 목록 확인 |
| 완료율 표시 | 해당 날짜의 할일 완료 비율(%) |

### 기능 2: 일일 회고 (Reflection)
| 항목 | 설명 |
|------|------|
| 회고 작성 | 오늘 한 일, 느낀 점, 내일 할 일 기록 |
| 할일 연동 | 회고 작성 시 오늘 완료한 할일 목록 자동 표시 |
| 회고 수정 | 작성한 회고 수정 가능 |
| 날짜별 조회 | 달력 또는 날짜 선택으로 과거 회고 열람 |

### 기능 3: AI 주간 요약 (선택/후순위)
| 항목 | 설명 |
|------|------|
| 주간 요약 생성 | 한 주간의 회고를 AI가 자동 요약 |
| 패턴 분석 | 자주 등장하는 키워드, 감정 변화 등 |

## 3. 기술 스택

| 영역 | 기술 | 선택 이유 |
|------|------|-----------|
| 프론트엔드 | React | 컴포넌트 기반 UI, 생태계 풍부 |
| 상태관리 | useState / useContext | 소규모 프로젝트에 적합, 라이브러리 최소화 |
| 스타일링 | CSS Modules 또는 Styled-components | 컴포넌트 단위 스타일 관리 |
| 백엔드 | Node.js + Express | JavaScript 통일, 빠른 API 개발 |
| 데이터베이스 | MongoDB + Mongoose | JSON 기반 유연한 구조, MERN 스택 |
| AI (선택) | Ollama | 무료 로컬 LLM, 주간 요약 기능용 |
| 배포 | Vercel(프론트) + MongoDB Atlas(DB) | 무료 호스팅, 간편한 배포 |
| 버전관리 | Git + GitHub | 포트폴리오 공개, 커밋 이력 관리 |

## 4. 데이터 구조 (MongoDB)

### Todo 컬렉션
```json
{
  "_id": "ObjectId",
  "title": "React 컴포넌트 공부",
  "category": "학습",
  "completed": false,
  "date": "2026-04-01",
  "createdAt": "2026-04-01T09:00:00Z"
}
```

### Reflection 컬렉션
```json
{
  "_id": "ObjectId",
  "date": "2026-04-01",
  "done": "React useState 훅 학습 완료, 블로그 글 작성",
  "feeling": "컴포넌트 구조가 점점 이해되고 있어서 뿌듯하다",
  "tomorrow": "useEffect 훅 학습 시작",
  "createdAt": "2026-04-01T22:00:00Z",
  "updatedAt": "2026-04-01T22:30:00Z"
}
```

## 5. API 설계

### Todo API
| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/todos?date=2026-04-01` | 특정 날짜 할일 조회 |
| POST | `/api/todos` | 할일 추가 |
| PATCH | `/api/todos/:id` | 할일 수정 (완료 토글) |
| DELETE | `/api/todos/:id` | 할일 삭제 |

### Reflection API
| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/reflections?date=2026-04-01` | 특정 날짜 회고 조회 |
| GET | `/api/reflections?start=2026-03-25&end=2026-03-31` | 기간별 회고 조회 (주간 요약용) |
| POST | `/api/reflections` | 회고 작성 |
| PATCH | `/api/reflections/:id` | 회고 수정 |

## 6. 화면 구성

### 페이지 목록
1. **메인 (대시보드)** - 오늘의 할일 + 회고 작성을 한 화면에서
2. **캘린더 뷰** - 날짜별로 할일/회고 조회
3. **주간 요약** - AI 요약 결과 (후순위)

### 주요 컴포넌트
```
App
├── Header (날짜 표시, 네비게이션)
├── MainPage
│   ├── TodoSection
│   │   ├── TodoInput (할일 입력)
│   │   ├── TodoList (할일 목록)
│   │   │   └── TodoItem (개별 할일)
│   │   └── ProgressBar (완료율)
│   └── ReflectionSection
│       ├── CompletedTodos (완료한 할일 자동 표시)
│       └── ReflectionForm (회고 작성 폼)
├── CalendarPage
│   ├── Calendar (달력)
│   └── DayDetail (선택한 날짜의 할일 + 회고)
└── WeeklySummaryPage (후순위)
```

## 8. 포트폴리오 어필 포인트

- **CRUD 완성도**: 할일/회고 전체 생성·조회·수정·삭제 구현

- **컴포넌트 설계**: 재사용 가능한 구조, props/state 관리
- **API 설계**: RESTful한 엔드포인트, 적절한 HTTP 메서드 사용
- **실사용 경험**: "직접 매일 사용하고 있습니다" → 면접 스토리
- **배포 경험**: Vercel + MongoDB Atlas 실서비스 운영
- **AI 활용** (선택): Ollama를 활용한 자연어 요약 기능
